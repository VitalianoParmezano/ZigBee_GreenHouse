# 🌿 Zigbee GreenHouse (ESP32-H2)

Прошивка ESP32-H2 для керування теплицями (клієнт-серверна архітектура).


## Універсальна конфігурація

Гілка `esp32_universal` підтримує PWM і Modbus RTU на ESP32-H2.
Налаштування режимів — у `components/project_config/include/project_config.h`.
Залиште розкоментованим рівно один рядок:

```c
#define PROJECT_MODE_PWM
// #define PROJECT_MODE_MODBUS
```

Для Modbus закоментуйте PWM і розкоментуйте Modbus, перебудуйте та прошийте пристрій.
Якщо вибрано обидва режими або жодного, збірка завершиться помилкою.

- PWM: charge pump одразу, дімінг 99% без затримки; GPIO10 прямий, GPIO1 інвертований, GPIO5 charge pump. Офлайн-перехід до 100% за 10 секунд.
- Modbus: TX GPIO0, RX GPIO1, RTS GPIO2, 115200 бод, broadcast-адреса 0, таймаут 1 мс, як у `modbus_testing`. Стартові значення не надсилаються; це можна ввімкнути через `PROJECT_MODBUS_APPLY_STARTUP`. Офлайн-рівень надсилається одразу, без плавного переходу.
- У Modbus режимі PWM та його ранні рівні GPIO не активуються.
- У конфігурації доступні піни, частоти, стартові відсотки, офлайн-рівень і таймаут сервера (типово 180 секунд). При зміні плати перевірте конфлікти пінів із DIP, кнопкою й LED.
- Спеціальна послідовна логіка гілки `channelSequence` сюди не переносилася.

Наведений нижче опис PWM стосується типових налаштувань цього режиму.

## Архітектура

Головна концепція полягає в клієнт-серверній архітектурі. При ініціалізації PWM charge pump запускається одразу на ≈50%. Одразу після налаштування прямого та інвертованого виходів дімінг PWM встановлюється на 99% без затримки і змінюється лише командою сервера. Приєднання до Zigbee не змінює яскравість. Якщо протягом 180 секунд немає відповіді heartbeat (`boot_status = 1`, EP 2, кластер `0xFF01`, атрибут `0x0000`), PWM плавно переходить від поточного рівня до 100% приблизно за 10 секунд. Нова команда дімінгу перериває цей перехід. Після відновлення heartbeat вихід залишається на 100% до нової команди дімінгу. Уся логіка знаходиться на вищих рівнях (Z2M / HA / LogicService), ESP лише керує яскравістю.

| GPIO | Сигнал |
| :--- | :--- |
| 10 | Дімінг, 300 Гц, 10 біт, 0–100%; при старті 99% без затримки. Керується каналом 1 (EP 11). |
| 1 | Інвертована копія GPIO10: при дімінгу 100% тут постійний LOW. |
| 5 | Charge pump, 100 кГц, 8 біт, фіксовано близько 50%; не змінюється командами дімінгу чи таймаутом. |

Прошивка написана на C з використанням ESP-ZIGBEE-SDK та розбита на незалежні модулі. Головний вузол ініціалізації Zigbee-мережі знаходиться у файлі `main/esp_zb_switch.c`.

| Компонент | Опис та призначення |
| :--- | :--- |
| **`greenhouse_light_control`** | Відповідає за створення ендпоінтів, їх ініціалізацію. А також за ledstrip. |
| **`modbus`** | Модуль трансляції протоколу modbus. Виконує роль Modbus RTU Master для конвертації бездротових Zigbee-команд у сигнали для драйверів освітлення. |
| **`heart_beat`** | Модуль реалізовує перевірку з'єднання з координатором. Кожні 50 + rand(20) секунд надсилає boot_status 2 після чого чекає на 1 |
| **`light_driver`** | Звідси відбувається безпосереднє керування освітленням, він надсилає дані по необхідним протоколам, тут налаштовується який саме протокол використати. |
| **`reset_configuration`** | Апаратний контроль конфігурації через DIP-перемикачі. Дозволяє фізично задавати номер групи або виконувати Factory Reset при натиску на кнопку 5 секунд. |
| **`PWM_control`** | Керування PWM вихідними сигналами, керується лише першим каналом. Має вихідний сигнал 300Гц для світильника і 100кГц для charge pomp. |

p.s. у випадку переконфігурації прошивки спершу треба заглянути у include/*.h файли, там прописані основні усі дефайни. 
Також не забудь перевірити `components/light_driver/light_driver.c`, там конфігуруєтся що саме буде йти на світильник

## Структура Ендпоінтів

Контролер реалізує нестандартні Zigbee ендпоінти і рішення для підтримки n зон по 3 канали кожна. Логіка наступна: ендпоінти каналів лежать починаючи з 11, тобто ендпоінт 12 це ендпоінт 2 каналу. Ендпоінт 2 у цій версії має лише атрибут boot_status, який використовується для сигналу heart_beat 

| Endpoint (EP) | Кластер (Cluster) | Атрибут (Attribute) | Опис функції |
| :--- | :--- | :--- | :--- |
| **EP 1** (System) | - | - | Базові атрибути потрібні для роботи Zigbee stack (назва моделі, опис ...) |
| **EP 2** (MetaData) | `0xFF01` (Custom) | `boot_status` 0x0000 | Статус початкової синхронізації, якщо == 0, тоді відбудеться синхронізація. |
| **EP 11** (Z1, Ch1) | `0x0008` (Level Control) | `current_level` 0x0000 | Поточна яскравість (0-254) першого каналу першої зони. |
|  | `0x0006` (State) | `State` 0x0000 | Стан on\off. |
| **EP 12** (Z1, Ch2) | `0x0008` (Level Control) | `current_level` 0x0000 | Поточна яскравість (0-254) другого каналу першої зони. |
|  | `0x0006` (State) | `State` 0x0000 | Стан on\off. |
