# LogicService

**LogicService** — це автономний Python-мікросервіс для  керування освітленням туплиць. Сервіс працює через MQTT-брокер, інтегрується із Zigbee2MQTT та керує мікроконтролерами (ESP32 / DALI), обчислюючи необхідну яскравість світла в реальному часі.

Головна архітектурна особливість — сервіс використовує періодичний "перерахунок з нуля" (tick-based). Якщо сервер перезавантажиться або зникне зв'язок, на наступному тіку система автоматично підтягне правильний стан.

---

## ⚙️ Режими роботи каналів

Система підтримує незалежне налаштування кожного каналу освітлення:

| Режим | Опис | Джерело даних |
| :--- | :--- | :--- |
| **Manual** | Ручне статичне керування яскравістю (0-100%). Зміни застосовуються миттєво. | Web UI (`/set` payload) |
| **Timer** | Робота за заданим графіком (наприклад, 22 години світла / 2 години темряви).  | Локальна БД (`scenarios`) |
| **Auto** | Режим **Daylight Harvesting**. Система бере цільове значення з графіка, порівнює його з реальними даними PPFD-сенсора сонця та динамічно вираховує дефіцит світла, коригуючи потужність лампи. | Локальна БД + MQTT Сенсор |

## Структура проєкту та призначення файлів

Проєкт розділено на логічні модулі за принципом "Separation of Concerns" (математика окремо, мережа окремо, база даних окремо).

### Кореневі файли
*   **`main.py`** — Точка входу в програму. Ініціалізує та запускає `SchedulerService`, а також перехоплює аварійні зупинки для зручного дебагу.
*   **`config.yaml` / `config.example.yaml`** — Глобальні налаштування середовища: параметри підключення до MQTT, кількість зон та каналів, інтервал тіку (tick interval) та рівень логування.
*   **`demo_resolve.py`** — Автономна утиліта (CLI) для тестування та візуалізації алгоритму розрахунку таймерного розкладу в консолі без запуску MQTT-брокера.
*   **`requirements.txt`** — Список залежностей Python (наприклад, `paho-mqtt`, `PyYAML`).
*   **`Dockerfile` / `.dockerignore`** — Інфраструктурні файли для пакування сервісу в ізольований Docker-контейнер із налаштуванням правильного часового поясу (tzdata).

### Директорія `scheduler/` (Ядро системи)
*   **`config.py`** — Модуль завантаження та валідації налаштувань із `config.yaml`. Перетворює сирі конфіги на зручні Python-об'єкти (settings).
*   **`service.py`** — Головний оркестратор. Містить безкінечний цикл `_tick()`, який раз на N секунд опитує базу даних, перебирає всі зони/канали, делегує математичні розрахунки та вирішує, чи потрібно надсилати нову команду на лампи.
*   **`mqtt_state.py`** — MQTT-шар. Відповідає за підключення до брокера, підписку на топіки, обробку вхідних команд керування та публікацію команд для реальних пристроїв у простір `zigbee2mqtt/`.
*   **`store.py`** — Потокобезпечний (Thread-safe) менеджер локальної бази даних SQLite. Зберігає налаштування режимів та графіків (`channel_config`), а також апаратні ліміти потужності ламп (`lamp_config`), виступаючи "єдиним джерелом правди".
*   **`schedule_logic.py`** — Модуль чистої математики. Не має доступу до мережі чи БД. Парсить текстові розклади, обчислює цільовий відсоток яскравості на поточну хвилину доби та містить логіку П-регулятора для компенсації денного світла.

## MQTT Контракт (API)

Усі комунікації з веб-інтерфейсом та датчиками відбуваються у просторі `LogicService/*`.

| Топік | Напрямок | Призначення |
| :--- | :--- | :--- |
| `LogicService/Zone_X_Channel_Y/set` | **ВХІД** | Команди від UI на зміну режиму, яскравості або розкладу (JSON). |
| `LogicService/Zone_X_Channel_Y/get` | **ВХІД/ВИХІД** | Запит поточного стану каналу. Сервіс відповідає у цей же топік. |
| `LogicService/Zone_X_Channel_Y` | **ВИХІД** | Retained broadcast. Сервіс публікує сюди повний стан після будь-яких змін (зручно для відображення в UI). |
| `LogicService/bridge/sensor` | **ВХІД** | Глобальний показник PPFD датчика сонця. Використовується для Авто-режиму `{"umol": 1500.0}`. |
| `LogicService/bridge/max_umol` | **ВХІД** | Оновлення параметрів максимальної потужності світильників `{"1": 250.0}`. |
| `zigbee2mqtt/Zone_X.../set` | **ВИХІД** | Реальні команди для кінцевих пристроїв ESP32. |

## Запуск та експлуатація

Перед запуском необхідно створити конфіг файл, приклад виглядає наступним чином:
```yaml
mqtt:
  host: 127.0.0.1
  port: 1883
  user: ""
  password: ""
  base_topic: zigbee2mqtt

scheduler:
  zones: 8
  channels_per_zone: 3
  tick_interval_sec: 30
  # true = сервіс тільки логує, що б відправив, нічого не публікує в /set
  dry_run: false

logging:
  # DEBUG - показує кожен канал на кожному тіку (навіть коли нічого не
  # змінилось) і чому саме пропущено. INFO (за замовчуванням) - лише реальні
  # події: підключення, SET-команди від картки, фактична зміна яскравості.
  level: INFO
  # Тека для файлових логів (відносно кореня проєкту - там же, де main.py).
  # У Docker це всередині bind volume, тож видно і на хості.
  dir: logs
  # Скільки останніх днів логів зберігати - старіші файли видаляються
  # автоматично щоночі, папка ніколи не розбухає необмежено.
  retention_days: 2
```
